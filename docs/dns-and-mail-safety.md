# DNS 변경과 다음 스마트워크 보호

## 현재 상태

2026-09-02 읽기 전용 조회에서 권한 네임서버는 `ns1.whoisdomain.kr`부터 `ns4.whoisdomain.kr`까지 확인됐습니다. 네임서버는 변경하지 않습니다. 후이즈 회사 계정에서 해당 도메인 목록을 확인했으나 전체 zone export는 아직 확보되지 않았습니다. 관리 화면의 설정 다운로드가 브라우저에서 차단되어 파일을 받지 못했습니다. 백업이 확보되기 전에는 DNS 수정 단계로 넘어가지 않습니다.

**아직 DNS 변경 없음.** 공개 조회는 알려진 호스트만 확인할 수 있으므로 전체 TXT, 알려지지 않은 DKIM selector, 모든 TTL의 백업으로 간주하지 않습니다. 전체 관리 화면/내보내기 백업을 확보하기 전에는 변경하지 않습니다. 상세 조회 결과와 기존 값은 Git에 포함하지 않는 `local-only/`에 저장합니다.

## 변경 가능한 대상

배포·custom domain 설정과 백업이 완료된 뒤 공식 값과 다시 대조합니다.

| 이름 | 타입  | 목표 값                                                               |
| ---- | ----- | --------------------------------------------------------------------- |
| @    | A     | 185.199.108.153 / 185.199.109.153 / 185.199.110.153 / 185.199.111.153 |
| @    | AAAA  | 2606:50c0:8000::153 / 8001::153 / 8002::153 / 8003::153 (동일 접두어) |
| www  | CNAME | gimoxagros.github.io.                                                 |

표는 **계획이지 적용 내역이 아닙니다**. 적용 시 AAAA의 각 전체 주소를 공식 문서와 확인하고 공급자 지원 여부와 실제 TTL을 기록합니다. apex CNAME이나 wildcard는 만들지 않습니다. 기존 CAA, DNSSEC, 메일 호스트, 인증 TXT는 임의 변경하지 않습니다.

## 메일 보존

현재 운영값이 기준입니다. Daum 기본값을 이유로 기존 통합 SPF를 덮어쓰거나 SPF TXT를 중복 추가하지 않습니다. MX 우선순위, SPF, DKIM selector, `_dmarc`, Autodiscover, mail/webmail/smtp/imap/pop, 관련 인증 TXT/CNAME 및 TTL을 그대로 보존합니다.

변경 전에 모든 레코드의 호스트·타입·우선순위·값·TTL을 관리자 화면에서 보관합니다. 변경 후에는 권한 서버와 1.1.1.1, 8.8.8.8의 결과를 확인합니다. 따옴표·끝 마침표·응답 순서를 정규화한 다음 메일 레코드의 논리적 동일성을 비교합니다. 값을 확인하지 못한 DKIM을 “보존 검증 완료”로 보고하지 않습니다.

```powershell
Resolve-DnsName dw-tec.co.kr -Type MX -Server 1.1.1.1
Resolve-DnsName dw-tec.co.kr -Type TXT -Server 8.8.8.8
Resolve-DnsName _dmarc.dw-tec.co.kr -Type TXT -Server ns1.whoisdomain.kr
Resolve-DnsName www.dw-tec.co.kr -Type CNAME -Server 1.1.1.1
```

## 남은 검증

- 관리자 전체 레코드/TTL 백업: 대기
- 웹 DNS 적용: 미실행
- 메일 레코드 전후 동일성: 변경 전이므로 아직 최종 비교 불가
- 실제 회사 메일 송수신·회신과 헤더 검사: 미실행
- 메일 장애 시 웹용 레코드만 이전 백업으로 복원

회사 메일 테스트에는 회사가 지정한 시험 상대와 메일 계정 사용 승인이 필요합니다. DNS가 같다는 사실만으로 실제 송수신 성공을 단정하지 않습니다.
